## Scope and comparison

Reviewed against upstream `master` at `ae49d169be9e5a930007a752f79d215297a693bd`, after PRs #277-#282 merged. GitHub listed **169 publicly visible forks**, despite the repository counter showing 182. All **305 visible branches** were compared, including **136 non-default branches**. No comparison requests failed. The [branch inventory](fork-inventory-2026-09-26.csv) pins the exact fork tips and merge bases.

**29 default branches** contain commits absent from the upstream ancestry. Of the non-default branches, 121 contain absent commits, but only **22 additional distinct tips** remain after removing tips already seen on default branches and deduplicating identical copies. In particular, 97 forks retain the same old `0.7.0-pre` tip. Commit counts are ancestry comparisons, not proof of missing functionality: several changes already exist under different commits or were replaced by the recent repairs.

The review screened every branch's commit/file metadata and read patches for relevant changes. MelleD's default branch was fetched for a full local diff. This is a source/documentation comparison, not certification of every fork's runtime or an Amazon deployment. GitNexus has no indexed repository in this session, so no graph-backed coverage is claimed. Private/deleted/inaccessible forks and separate wiki histories are outside this inventory.

## MelleD: bring in a corrected guide, port Tailscale separately

[MelleD's reviewed main tip](https://github.com/MelleD/alexa-actions/tree/9e805dffe371656745a64ac2b3a6ba75d4d548ee) has 11 unique commits and shares merge base `a1a1e5501d909431fd434afb686fb3b16e3ede80` with upstream. It documents a self-managed Tailscale container deployment, rather than a replacement for the standard Alexa-hosted/ZIP setup. The [new setup walkthrough](alexa-setup.md) credits that work and separates the routes. The earlier [Tailscale proposal #251](https://github.com/keatontaylor/alexa-actions/pull/251) is closed; it uses the fork's older master branch, not its revised main README.

The following corrections are required before describing it as an upstream setup path:

- [HA's Tailscale integration](https://www.home-assistant.io/integrations/tailscale/) monitors the tailnet; it does not make HA reachable. A real client or suitable subnet route must be installed.
- ECR and Lambda must share a region, but the repository name and `eu-west-1` in the fork's workflow are chosen values, not fixed requirements. See [AWS container requirements](https://docs.aws.amazon.com/lambda/latest/dg/images-create.html).
- A ten-second HTTP/Lambda timeout does not extend Alexa's approximately eight-second response limit. See [Amazon response timing](https://developer.amazon.com/en-US/docs/alexa/custom-skills/send-the-user-a-progressive-response.html).
- Automated auth-key creation is available through Tailscale's OAuth/API options. Auth-key expiry and ephemeral device cleanup are separate concerns; see [auth keys](https://tailscale.com/docs/features/access-control/auth-keys).
- Fork configuration names differ: upstream uses `HOME_ASSISTANT_URL`, `TOKEN`, and `VERIFY_SSL` Python constants. `HA_URL`, `HA_TOKEN`, or `ALL_PROXY` environment variables do not enable this behavior in the upstream ZIP.

There are concrete reasons to avoid merging the runtime patch unchanged. The fork's [HomeAssistant initializer](https://github.com/MelleD/alexa-actions/blob/9e805dffe371656745a64ac2b3a6ba75d4d548ee/lambda/lambda_function.py) sets `bearer_token` but then reads `self.token` without initializing it. Its [config defaults](https://github.com/MelleD/alexa-actions/blob/9e805dffe371656745a64ac2b3a6ba75d4d548ee/lambda/config.py) disable SSL verification and leave environment booleans as strings. Its [entrypoint](https://github.com/MelleD/alexa-actions/blob/9e805dffe371656745a64ac2b3a6ba75d4d548ee/custom_entrypoint) retries tailnet authentication without a deadline. Its SOCKS manager does not inherit the direct pool's configured verification/timeout settings, and its dependencies are unbounded. It also retains Borg state instead of the corrected session snapshot behavior.

A future Tailscale PR should keep the current session/error implementation, add a tested proxy transport and validated private settings, use bounded cold-start/authentication behavior, choose maintained runtime/image/dependency versions, and test expiry, refused connections, cold/warm starts, and concurrent sessions. Local Docker smoke tests can cover the container and proxy, but a development AWS/tailnet deployment is still needed to prove the cloud route. This guide PR does not add or claim that deployment support.

## Follow-up candidates

After the corrected guide, useful independent proposals are: a maintained optional Tailscale deployment; custom confirmation speech/confirm-before-post with session-safe state; a complete `fr-CA` model; and scoped Assist or APL support. Hindi and Mexican Spanish need complete locale work rather than importing a partial old translation. Each deserves a separate issue/PR, its own contract tests, and the required Amazon model/account or device feedback. None of these feature candidates is declared fixed by this documentation PR.

Existing equivalents are retained in upstream. No fork branch was merged wholesale, and no new AWS resource, tailnet device, credential, or physical Alexa test was created during this review.
